# Модель безопасности PhoneMic v1

## Угрозы и контрмеры

| Угроза | Контрмера |
|---|---|
| Подслушивающий в сети (mitm/sniffing) | Весь трафик зашифрован: control — TLS 1.2/1.3 (или RFCOMM-шифрование BT + AES-GCM), медиа — AES-256-GCM на каждый пакет. |
| Несанкционированное подключение к микрофону | Авторизация 32-байтным токеном: сервер присылает nonce, клиент отвечает HMAC-SHA256(token, nonce‖context). Токен в сеть не передаётся. Сравнение HMAC — `CryptographicOperations.FixedTimeEquals` (защита от timing-атак). |
| Подмена сервера (фальшивый ПК) | TOFU-пиннинг: при первом подключении телефон показывает SHA-256 отпечаток сертификата, пользователь сверяет с ПК. Отпечаток сохраняется; при смене — соединение разрывается с ошибкой. |
| Replay-атака на медиа | Нонсы = 4B-префикс сессии + 8B-счётчик (монотонный), приёмник отклоняет пакеты со счётчиком ≤ последнего принятого. |
| Второй клиент (конфликт сессий) | Сервер держит одну сессию, остальным отвечает `err: busy`. |
| Утечка токена из файлов ПК | `settings.json` в профиле пользователя, токен никогда не логируется; в UI показывается по кнопке. На телефоне токен в EncryptedSharedPreferences (AES256-GCM, ключ в Android Keystore). |
| Несанкционированный доступ к control-устройству драйвера | `IoCreateDeviceSecure` с SDDL: SYSTEM/Admins — полный, Users — чтение/запись (нужно для подачи звука из приложения). Изменить — только администратор. |
| Заливка шума в микрофон другим процессом | Учтённое ограничение: подавать PCM может любой процесс текущего пользователя с правом на устройство. Для ужесточения замените `GRGW` для `BU` на конкретный SID в `phonemic_ioctl.h` (SDDL) и пересоберите. |
| Переключение сертификата/токена у легитимного ПК | Смена сертификата → phone отклонит пин; смена токена — пользователь сам вводит новый. |

## Гигиена ключей

- Токен генерируется `RandomNumberGenerator.GetBytes(32)` (CSPRNG), представление — base64url (43 символа).
- Ключи медиа = HKDF-SHA256(SHA256(token), salt=32B из handshake, info) — даже при утечке `media_salt` без токена ключи не восстанавливаются.
- Сертификат сервера: RSA-3072, 10 лет, хранится в `%LOCALAPPDATA%\PhoneMic\server.pfx` с паролем из CSPRNG (рядом в settings.json — угроза ограничена профилем пользователя; для повышенных требований перенесите в хранилище сертификатов Windows).

## Приватность Windows

Драйвер регистрируется как обычное аудиоустройство класса MEDIA, поэтому стандартный
переключатель «Параметры → Конфиденциальность → Микрофон» работает: приложения без
разрешения не получат звук.

## Что НЕ защищено в v1

- Discovery-запросы/ответы (UDP 47820) передаются открыто (содержат только имя ПК/телефона и отпечаток) — это принципиально: они не дают доступа к звуку.
- Сообщения handshake до `ok` в Bluetooth-режиме — открытый JSON внутри шифрованного RFCOMM-канала Bluetooth (токен всё равно не передаётся).
- Отсутствует защита от физического доступа к ПК (токен лежит в файле профиля).
